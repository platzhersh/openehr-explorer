Prerequisites

openEHR Explorer is a native desktop application. It has minimal system requirements and ships as a self-contained binary with no runtime dependencies.

Supported Platforms

  • macOS 12 (Monterey) or later
  • Windows 10 (version 1803) or later
  • Linux Ubuntu 22.04+ or equivalent (glibc 2.35+, WebKitGTK 4.1)

What You Don't Need

Unlike many clinical data tools, openEHR Explorer does not require Java, Docker, Node.js, or any other runtime to be installed on your machine. Everything is bundled into a single application.

  • Approximately 10 MB of disk space
  • A running openEHR CDR instance to connect to (EHRBase, Better Platform, or any standards-compliant server)

Installation

Download the latest release for your platform from GitHub Releases.

macOS

  1. Download the .dmg file from the latest release
  2. Open the DMG and drag openEHR Explorer to your Applications folder
  3. On first launch, right-click the app and select "Open" to bypass Gatekeeper (since the app is not yet notarized)

Windows

  1. Download the .msi installer from the latest release
  2. Run the installer and follow the prompts
  3. Launch openEHR Explorer from the Start Menu

Linux

  1. Download the .AppImage file from the latest release
  2. Make it executable and run it:
chmod +x openehr-explorer_0.1.0_amd64.AppImage
./openehr-explorer_0.1.0_amd64.AppImage

Note: openEHR Explorer is currently in early development. Check GitHub Releases for the latest version.

First Connection

After installation, follow these steps to connect to your first openEHR CDR:

  1. Launch the app. You will see the Server Manager by default on first run.
  2. Go to Server Manager. Click "Servers" in the sidebar navigation.
  3. Click "+ Add Server" to create a new server profile.
  4. Enter the connection details:
    • Server name — A friendly label (e.g., "Local EHRBase")
    • Base URL — The root URL of your CDR (e.g., http://localhost:8080/ehrbase)
    • Server type — Select EHRBase, Better Platform, or Generic
  5. Choose an authentication method:
    • None — No authentication (development servers)
    • Basic — Username and password
    • Bearer — OAuth2 or API token
  6. Click "Test Connection" to verify the app can reach your CDR.
  7. Click "Save" to store the profile.
  8. Select the server from the sidebar switcher. You are now ready to browse EHRs, templates, and run AQL queries.

Server Manager

The Server Manager is your central place for configuring connections to openEHR CDR instances. You can manage as many server profiles as you need and switch between them at any time.

  • Multiple profiles — Keep separate profiles for development, staging, and production servers.
  • Server type support — Built-in compatibility with EHRBase, Better Platform, and generic openEHR REST servers. The server type determines how API URLs are constructed.
  • Flexible authentication — Supports no auth, Basic (username/password), and Bearer token authentication.
  • Connection testing — Verify that your server is reachable before saving the profile. The test checks both network connectivity and API availability.

Server profiles are stored locally on your machine and never transmitted anywhere. See Server Profiles for details on storage and configuration.

EHR Browser

The EHR Browser provides a paginated list of all Electronic Health Records on the connected server.

  • Paginated listing — Browse through all EHRs with server-side pagination. Each entry shows the EHR ID and creation timestamp.
  • Composition grouping — Click any EHR to expand it and see its compositions organized by template. This gives you a quick overview of what clinical data exists for a patient.
  • Create new EHRs — Click "+ New EHR" to open the creation dialog. You can optionally provide subject identity details (external reference, namespace) and configuration flags.
  • Delete EHRs — Remove an EHR and all its compositions. As a safety measure, you must type the full EHR ID to confirm deletion.

Composition Viewer

The Composition Viewer lets you inspect any composition in three different representations side by side.

View Modes

  • Pretty — A structured, human-readable tree view of the composition data. Nodes can be expanded and collapsed.
  • JSON — The raw canonical JSON representation as returned by the openEHR REST API.
  • FLAT — A denormalized key-value view using FLAT paths. This is especially useful for developers working with openEHR SDKs.

Path Panel

The right-hand path panel shows every FLAT path derived from the Web Template. Click any path to copy it to your clipboard instantly.

Version Navigation

If a composition has been updated, you can navigate between all available versions to see how the data changed over time.

Edit and Delete

Use the toolbar buttons to edit the composition (opens the composition form pre-populated with existing data) or delete it entirely.

Template Browser

The Template Browser lists all operational templates uploaded to the connected CDR and lets you explore their structure.

  • Template listing — View all templates with their IDs and descriptions.
  • Web Template inspector — Click a template to load its Web Template representation and explore the tree structure. Each node shows its type, constraints, and FLAT path.
  • OPT upload — Upload Operational Template (OPT) XML files directly to the CDR from the browser.
  • Compose from template — Click "New Composition" on any template to jump straight into the composition form with that template pre-selected.

AQL Runner

The AQL Runner is a dedicated workspace for writing and executing Archetype Query Language queries against your CDR.

  • Query editor — Write AQL queries with syntax highlighting in a resizable editor pane.
  • Execute queries — Run your query with Ctrl+Enter (or Cmd+Enter on macOS) and see results instantly.
  • Tabular results — Results are displayed in a sortable table with column headers derived from the query projection.
  • Saved queries — Save frequently used queries for quick access. Saved queries persist across sessions.
  • CSV export — Export result sets as CSV files for use in spreadsheets or data analysis tools.

Coming in v0.2.0: AQL autocomplete with archetype-aware suggestions.

FLAT Path Panel

The FLAT Path Panel is available in both the Composition Viewer and the Template Browser. It is designed for developers who need to work with the FLAT composition format programmatically.

  • Full path display — Shows the complete FLAT path for every node in the Web Template tree.
  • One-click copy — Click any path to copy it to your clipboard. A visual confirmation appears briefly.
  • SDK development aid — Particularly useful when building FLAT compositions in code. Instead of manually constructing paths from the template definition, you can browse the tree and copy paths directly.

Server Profiles

Server profiles are stored as JSON on your local filesystem. They are never sent to any external service.

Storage Location

  • Linux / macOS: ~/.config/openehr-explorer/profiles.json
  • Windows: %APPDATA%\openehr-explorer\profiles.json

Server Types

The server type determines how API endpoint URLs are constructed:

Type API Base Path Example
EHRBase /rest/openehr/v1/... http://localhost:8080/ehrbase/rest/openehr/v1/ehr
Better Platform /rest/v1/... https://cdr.example.com/rest/v1/ehr
Generic Configurable Any standards-compliant openEHR REST API

Authentication Methods

  • None — No authentication headers are sent. Suitable for local development servers without security enabled.
  • Basic — Sends an Authorization: Basic header with base64-encoded username:password. Credentials are stored locally in the profile file.
  • Bearer — Sends an Authorization: Bearer header with the provided token. Useful for OAuth2-protected servers or API key access.

Keyboard Shortcuts

openEHR Explorer supports the following keyboard shortcuts to speed up common actions:

Shortcut Action
Ctrl/Cmd + 1 Switch to EHR Browser
Ctrl/Cmd + 2 Switch to Template Browser
Ctrl/Cmd + 3 Switch to AQL Runner
Ctrl/Cmd + 4 Switch to Server Manager
Ctrl/Cmd + 5 Switch to Composition Viewer (when available)
Ctrl/Cmd + Enter Execute AQL query (in AQL Runner)
Escape Close dialogs and modals

Troubleshooting

"Connection refused" when testing a server

This means the app cannot reach the server at the specified URL. Verify that:

  • The CDR is running and accepting connections
  • The base URL is correct (check the port number and path)
  • No firewall is blocking the connection
  • If connecting to a remote server, ensure VPN or network access is configured

"401 Unauthorized" errors

The server rejected your credentials. Double-check the authentication settings in your server profile:

  • For Basic auth, verify the username and password
  • For Bearer auth, ensure the token has not expired
  • Confirm the auth method matches what the server expects

"CORS errors" in the console

openEHR Explorer uses Tauri's native HTTP client, which is not subject to browser CORS restrictions. If you see CORS errors, you are likely running a development build in the browser. Use npm run tauri dev instead of running the frontend alone with npm run dev.

Application does not launch on Linux

Ensure you have WebKitGTK 4.1 installed. On Ubuntu/Debian:

sudo apt install libwebkit2gtk-4.1-0

Found a bug? Please report it on GitHub Issues with steps to reproduce, your OS version, and the app version.
